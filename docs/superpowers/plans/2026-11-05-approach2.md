# Approach 2 and Shared Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compare readable Python and local Ollama extractors using shared procurement checks and evidence reporting.

**Architecture:** Keep `procurement.review` as the explicit workflow. Separate the extractors into `approach1/` and `approach2/`; move reusable code into `shared/`. Both approaches produce the same validated fact contract and use the same policy and evaluation.

**Tech Stack:** Python 3.11+, existing PyMuPDF==2.0, standard-library unittest/urllib/json/dataclasses, local Ollama with qwen2.5:7b. No new runtime dependency is planned.

**Spec:** `docs/superpowers/specs/2026-11-05-approach2-design.md`

## Global Constraints

- Keep changes on main as previously requested; commit each verified block.
- Leave unrelated video/ and original sample data untouched.
- All ten documents are development-visible, not a held-out test set.
- Approach1 must run without API access or the AI SDK installed.
- No OCR or automatic vision fallback.
- No policy thresholds, expected labels or sample-specific answer examples go into extraction.
- Preserve printed figures, including arithmetic mistakes.
- A clear independent rejection retains existing priority over uncertainty, with all review findings retained.
- No silent document truncation or remote fallback.
- Never count assisted decisions as unassisted AI accuracy.
- Explain the files and flow after each block unless the user requests uninterrupted execution.

## Review Focus

1. A model cites real text but changes its meaning: exact-evidence checks must not be presented as semantic verification (Blocks 2, 5).
2. A payment duration has the wrong reference event or an extra condition: never silently approve it (Block 2).
3. A model/service failure disappears from the accuracy denominator: retain all ten attempted files (Blocks 3, 5).
4. An extra item or blank page is ignored: preserve whole-document issues and escalate unsupported input (Blocks 2, 3).
5. A human correction is applied to a different file or run: reject mismatched identity and keep assisted metrics separate (Block 4).

## File map and interfaces

The spec contains the folder map. Also add `shared/human_review.py` for the small
local handoff and `shared/runs.py` for saved artifacts; these isolate two concrete
responsibilities instead of growing the CLI. Create package `__init__.py` files,
including under test subfolders so unittest discovery continues to recurse.

Shared records in `shared/extraction.py`:

- Keep `Evidence(page_number, text)` and existing `ExtractedField(value, status, evidence)`.
- Append defaulted fact attributes: `raw_value: str | None = None`,
  `reference_event: str | None = None`, `conditions: tuple[str, ...] = ()`,
  `minimum_value: str | None = None`, `maximum_value: str | None = None`.
  Values and bounds are decimal strings when numeric. These attributes preserve
  interpreted intervals and qualifiers; they are not new policy decisions.
- Add frozen `ExtractionRun(fields: dict[str, ExtractedField], issues: tuple[str, ...],
  metadata: dict, raw_response: str | None = None)`.
- Define `FACT_NAMES` explicitly: the union of the current supplier fields,
  financial `FIELD_NAMES`, term `FIELD_NAMES`, raw clause fields and reference
  fields. Add `currency` as an explicit fact. All runs must include every name;
  valid missing facts are not_found/null, not omitted dictionary keys.
- Existing metadata names are supplier_name, quotation_number, quotation_date,
  purchase_request_reference, tin and bin. Raw clauses are payment_clause_text,
  delivery_clause_text, penalty_clause_text and validity_clause_text. Reference
  fields are payment_reference, delivery_reference and validity_reference.

Both extractors expose `extract_document(document: PdfDocument, ...) -> ExtractionRun`.
The baseline has no extra arguments; Ollama's extractor accepts explicit keyword
arguments `model`, `endpoint`, `timeout`. Use direct function selection in the CLI.

Keep `review_document(path, items, policy)` compatible; add optional keyword arguments
`approach='approach1'`, `model='qwen2.5:7b'`, `endpoint='http://localhost:11434'`,
`timeout=180.0`, `artifact_dir=None`. Append defaulted `extraction_run` and `steps`
attributes to ReviewResult so existing callers can still construct it.

## Block 2: Common fact contract, semantic safeguards and AI prompt

- [x] Add failing tests asserting: 45 days after invoice cannot satisfy an

  A separately established price rejection still wins over those review findings.
- [x] Add failing schema tests for absent required keys, extra keys, bool-as-page,
  unknown status, NaN/negative/oversized numbers, found/null combinations,
  contradictory bounds, invented excerpts, wrong pages and duplicate JSON keys.
  Assert valid not_found/null has no invented evidence. Explicitly test valid
  excerpts with an incorrect interpretation remain possible and need field audit.
- [x] Implement the shared records and explicit FACT_NAMES. Adapt baseline output
  without weakening its parser: copy existing reference fields into the duration
  facts and preserve unrecognized/ambiguous statuses. Currency is found BDT only

- [x] Define strict JSON Schema with required named facts and no extra properties.

- [x] Write prompt.txt using the design's general extraction instructions.
